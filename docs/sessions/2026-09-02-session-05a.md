## 踩坑 / 经验

- **坑（阶段 2 审核抓获，计划级）**：包装/装饰构造器里的对象展开（`{ ...options, id }`）是 getter 的冻结点——「getter-backed options 热读」前提不成立。修复 = 透传原对象 + 移除零消费的 id 契约面。教训：热路径对象必须按引用传递，展开即快照
- **坑（快解）**：cordis 用 Proxy 包装插件类实例，真 `#private` 字段经 Proxy 不可见（`Cannot read private member`）——测试 fixture 类字段用公开属性（上游 MemorySettings 同此因）
- **坑（阶段 4 抓获，F-1）**：门墙数字「先测后改」时序坑——T8 同批改 config.ts JSDoc 流入 .d.ts，台账数字相对 HEAD 陈旧。修复 = HEAD 重跑 + 台账留痕。与 S04 的 tail 截断同属「验收数字失实」家族：**门墙数字必须在收口批内容零 src 变更后采集**
- **经验**：真实 seam 测试（new Context + MemorySettings extends SettingsProvider）可以直接驱动 installSection 全生命周期（attach→update→detach fallback），「实测」二字从 fake 假设升级为服务级事实——上游 spec 先例 + devDep 类型增强使然
- **经验**：链序热改断言用「全 500 stub + exhausted 摘要成员序」代替 spy 调用序数组——由链核实际遍历派生，行为等价且断言更直接
- **经验**：pnpm install 会自动追加 minimumReleaseAgeExclude——S04 的 F-1 教训在本棒 T-prep 直接兑现（workspace 追加行随批提交），零残留
