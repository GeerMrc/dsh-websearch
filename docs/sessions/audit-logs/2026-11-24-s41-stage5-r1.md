**事实**

**随包补丁禁用了哪一行、影响面**
- `cordis.patch.yml:21-22` 只禁用 `ui-settings-web-search`，在 bundle 层，没有 `name` 守卫。

**可见入口**

- 钉值残留加插件关闭不是死局（M4）；逃生口可用（M7）。

**发布门的放行路径**
- 令牌扫描对 git 判为二进制的已跟踪文件放行。带 NUL 的文件，`git grep` 只输出 `Binary file … matches`；UTF-16 这类日志同理。实验见 `b-token-scan-binary-probe.txt`。
- tarball 校验是「必需成员都在，且没命中黑名单」，不是精确成员集。
- 仓库的分支保护设置不在仓库内，我没核。

**泄露路径**
- `scripts/check-release.mjs:99-106` 命中时只输出 `文件:行号`，测试已锁定。
- `GH_TOKEN` 只在 GitHub Release 一步的 env 里。
- 诊断步 `.github/workflows/release.yml:75-76` 只打印 npm `oidc` 记录器的行。这些行是否可能带凭据值，我没能核实。
- 两份工作流的 checkout 没设 `persist-credentials: false`。release 作业的令牌含 `contents: write`，后面还要装依赖、跑测试。不进日志，但工作流内的依赖代码读得到。
- 第三方 action 只钉了大版本，而这个工作流持有 `id-token: write`。
