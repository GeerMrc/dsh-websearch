## 踩坑 / 经验

- **坑（活端口纪律）**：keyPool 工厂首版把 refs 端口写成载入期静态数组——热增 ref 永不
  生效且 typecheck/lint 全不拦，靠 T4 ② pre-stored-key 行为测试红出来（阶段 2 必改 1
  的事前警告在实现期仍然命中）。教训：**live 语义的端口必须有「提交后生效」的行为测试**
  （构造期快照类 bug 只能被热断言抓到）
- **坑（TDD 时序与批次合并）**：T4 机制在 T3 已落地 → 先红不可得——诚实处置 = 变异
  探针证牙齿（红签名入 commit）+ commit message 披露分类偏移；同理 T5/T6 因 SectionProps
  签名变更合并为一个红绿批——**批次边界服从门墙绿纪律，不服从任务表行数**
- **坑（lint warning 提交链内自查）**：T2 两次 amend 清 warning、T3/T4 各一次——本棒
  warning 全部在提交链内或紧随提交清偿，无一潜伏到下一棒（对比 S08 T1 warning 潜伏两棒
  被 T6 抓获）——「同一命令链先 lint 后 commit」已动作化
- **经验（空池错误归属）**：KeyPool 自抛 credentialMissing（消息列主 ref + 全池）而非
  委托 resolveMemberApiKey（只列单 ref）——计划与 ADR 正本冲突时以正本仲裁（阶段 2 必
  改 2 的教训：计划阶段引用 ADR 条款要逐字，不能凭记忆转述）
- **经验（wire 级断言）**：轮换的最终证据是 loopback 收到的 Authorization 头序列而非
  mock 调用参数——穿透 provider 真实请求路径的策略断言 + 变异探针（改策略 → 红签名
  变化）构成完整牙齿
