## 踩坑 / 经验

1. **提交链枚举不可信（两现入册 dont-do）**：给审核方交接 hash 清单凭记忆誊写会漏 docs-only 提交（S35 阶段 4 抓获：声称 13 实际 15）——交接只给范围锚点（起点+HEAD），审核方自行 `git log` 复核。dont-do.md「交接证据链」条目已立。
2. **spike 静态分析两次被实测推翻**：计划期判「晚 patch dns.lookup 无效→Socket 注入」，双版本实测反转（undici 按调用时属性访问）——seam 类结论必须以零外网依赖的可复跑实验为准（spike 脚本已入库成套件锁）。
3. **串行腿预算叠加是隐蔽超支**：DoH 腿 350 + 预检腿 350 = 实测 410-493ms——多腿预算必须共享单一 deadline（修复后 351-353ms，机制 350 截止+1-3ms 收尾）。
4. **`&` 带符号 int32 陷阱**：CIDR base/mask 解析必须 `>>> 0` 归一后再比较（T3 测试先红抓获）。
5. **restore 与 delegate 目标分离**：进程级 patch 的 disposer 必须还原「安装时捕获的模块真身」，不能还原测试注入的 delegation seam（T6 抓获）。
6. **无 Context 的展示件经模块级 store 取数**：toolview 行无 ctx——entry 注册 fetcher + 模块单例 store + 展开即拉取（T9 模式）。
7. **hot-read 成本先测再优化**：config+scopeHosts 每 lookup 热读实测 2-4 µs（阶段 5 F3）——缓存收益为零。
8. **沙箱 PATH 的 node 版本错位 = 静默秒退**（T11-D 事故）：agent shell 里裸 `node` 解析到 v20.18.3（< engines ^22.19），DSH web 进程退出码 0、零输出、无报错——极易误判为沙箱拦截/权限/配置损坏（本次曾疑 key 文件权限，实测权限 600 未动）。判别法：先 `node -v`，再最小监听复现排除沙箱。修复=一律 nvm 绝对路径。dont-do 入册（T2-❷）。
