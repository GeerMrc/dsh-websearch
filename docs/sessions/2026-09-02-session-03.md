## 踩坑 / 经验

- **坑（快解，未达 dont-do 门槛）**：tsdown 对 `type: module` 包默认吐 `.mjs`/`.d.mts`，与手写 exports 的 `.js`/`.d.ts` 不一致且 install 期不报错——`outExtensions` 显式钉死后 pack 清单才正确
- **经验**：npm 依赖的 published d.ts 自身有 packaging 缺口（dsh-llm 未声明 dsh-attachment）——`skipLibCheck: true` + src 侧编译期探测（`ctx satisfies { web: unknown }`）组合：不掩盖自身错误、不丢增强验证
- **经验**：schemastery 实例即验证器（`(data) => 归一化`，非法抛 ValidationError；空对象归一化为结构骨架），无 `.validate`；默认值不进 schema、一律 resolveConfig 显式兜底——与宿主 explicit > implicit 纪律同构
- **经验**：接口完备性迫使行为体先于断言落地时（available() 为 seam 抽象成员、循环必有终态），红仪式以**变异校验**兑现（同向变异→新测试全红→还原），独立审核 Agent 二次复现判定力成立——比「为了看红临时破坏实现」更诚实且留痕可考
- **经验**：oxlint 零配置对未使用的类型别名即报 warning——探测类声明用 `satisfies` 表达式内联进函数体，零死代码零豁免
