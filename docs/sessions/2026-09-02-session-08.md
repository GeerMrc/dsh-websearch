## 踩坑 / 经验

- **坑（e2e 线材）**：exa item 不带 `highlights` 会被 mapExaResult 丢弃 → 链成功返回空
  sources（首轮 3 场景全红，红因=测试线材非产品码）——e2e 线材必须按各成员的**归一化
  丢弃规则**供数，不是按 wire 形状照抄
- **坑（流程自证）**：T1 提交时 lint 只核了末行（files 数）没核 `Found` 行——迁移残留的
  未用导入 warning 潜伏两棒被 T6 门墙抓获。教训：lint 门墙核 `Found X warnings`
  原始行，不核派生行
- **坑（测试生命周期）**：fixture 在 helper 内创建时，调用方 try/finally 只保护「已交付」
  的 fixture——helper 内部失败路径要自己 catch-close（T7 🟡-1）
- **坑（CHANGELOG 锚点编辑）**：收官向 CHANGELOG 顶部插入新条目时用「--- + 下一条目标题」
  作 old_string 锚——标题被消费进 new_string 的替换里，S06/S05b 两条目标题先后被吞（本棒
  两次修复才复原）。教训：插入条目锚定在**上一条目尾部唯一行**（如跟踪节末行）上，
  new_string 完整保留锚行；提交前 `grep '^## ' CHANGELOG.md` 全量清点条目数
- **经验（可观察面断言）**：链层 reason = 成员 message 而非 code（core.ts:173-177）——
  e2e 断言要么写 message 事实（`<Label> search request failed`/`HTTP 429`），要么只在
  异常对象在手处断 code；「code 入摘要」类断言必须先对实现取证（阶段 2 M1 拦截的正是它）
- **经验（牙齿证明惯例）**：验证类任务（TDD 豁免域）的替代红手段 = 一次性变异探针
  （临时改装配/线材 → 目标断言红 → 还原），红签名入 commit message 不入库——
  b67bcf3 实录，可沉淀为治理流程通用实践（T7 前瞻③建议）
- **经验（429 线材）**：unfoldHttpErrorDetail 对 exa/perplexity 替换 message、对 tavily
  追加——带可展开 detail 的 body 会吃掉状态字样；断言「reason 含 HTTP xxx」时 body 用
  `{}` 且成员钉 tavily
