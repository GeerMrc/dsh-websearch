## 踩坑 / 经验

- **坑（流程，阶段 4/5 抓获）**：T6 对 section.spec.tsx 的类型修复（t 座 TranslateNS 签名）
  未随 T6 commit 入库，滞留工作区三棒——提交态门墙红了三棒（typecheck exit 2）而本地
  每次门墙都绿（脏树），直到独立验证用 `git archive` 对照实验才现形。教训：**commit 前的
  门墙必须在「staged/提交态」意义上覆盖全部已改文件**；`git status --short` 应是每个
  commit 的前置动作（本棒 T9 起已纳入动作序列）
- **坑（构建）**：tsdown 失败试跑也会清共享 outDir——client 配置（entry 未建）试跑失败把
  `lib/` 清空，连带把 pack 清单打缺（一度误判 npm/pnpm pack 语义反转，最小对照 probe 定谳
  files 数组压 .gitignore 本来成立，避免了错教训入档）。修复 = client 配置 `clean: false`
- **坑（TS）**：tsconfig `extends` 继承 root 的 `exclude`——client face 补 include 后仍
  TS18003 空集，须显式 `"exclude": []`；另宿主类型在 `@deepseek-ai/dsh-settings/types`
  子路径（根导出无 SettingsDescribeValue/SettingsNamespaceView）
- **坑（IAB 实测环境）**：playwright locator `click()` 在本环境持续挂起（fill/getAttribute/
  evaluate 正常）；坐标 cua.click 可用但 DOM 插入（Saved 反馈行）会使下方元素坐标漂移两连
  miss——**evaluate 合成 MouseEvent dispatch 是可靠点击路径**（React root 监听捕获冒泡）
- **经验**：设置卡按钮必须 per-member aria-label——5 张同名 Save/Clear 按钮是测试查询歧义
  也是屏读器歧义（a11y 与可测性同源）
- **经验**：发布版 ui-primitives 在 vitest 下必须 `server.deps.inline`（lib 运行时 import
  自家 CSS module，externalized 依赖绕过 vite 转换）——vitest.config.ts 三行解决
- **经验**：写通路六断言的判读顺序 = UI 状态翻转（快照）→ 服务端落盘实物（settings.yaml/
  .credentials.yaml）→ 事件链——三层证据各自独立可验，UI 假绿骗不过服务端文件
