## Spike：假设 / 验收标准 / 结论（Spike 通道三节正本）

### H1 外置 client half 可注入 settings.section 并用 locale/remote —— **成立（GO）**

- **假设**：外置 npm 包的 client half（`dsh.client.platform='web'` + `exports["./client"]`）经 profile 安装后可被分发加载，`ctx.slots.inject('settings.section', …)` 渲染设置页，`ctx.locale`/`ctx.remote` 可用
- **验收标准**：spike web 实例（scratch DSH_HOME + 非 3080 端口）浏览器 DOM 断言卡片出现、文案经 locale 字典渲染；分发请求 200
- **结论与证据**：成立。① boot 页面 HTML 收录 `dsh-websearch-spike`，combo 响应 200 / 5,117,724 bytes 含 `id: "dsh-websearch-spike"` 注册（curl 亲测）；单包 URL `/plugins/dsh-websearch-spike/client.js` 404——服务端仅回放预生成 combo（combo-only，不影响加载）。② 浏览器 DOM 断言（IAB 实测）：设置对话框导航出现「Web Search Spike」（en）/「网页搜索 Spike」（zh），节面板标题/挂载文案经字典渲染，语言 en↔zh 热切换后三项全部正确翻转（DOM 断言为亲测原文引用；截图产物不入库，spike 纪律）。③ 发现并修复一处使用纪律：`ctx.remote.settings` 须声明细粒度 inject `'remote.settings'`，漏声明时 fail-loud `cannot get property "remote.settings" without inject`（契约本身工作正常）。GO 定谳 = ADR-0006

### H2 `dsh plugin add` 本地路径安装端到端 —— **成立（两形态全通）**

- **假设**：`dsh plugin --profile web add <本地目录>`（scratch home）端到端可复现；tarball 形态等效
- **验收标准**：安装命令日志 + dependencies/`dsh.profile.bundles`/patch 三处落盘实测 + boot 零 load 错误；tarball 对比
- **结论与证据**：成立。本地目录腿：`+ dsh-websearch-spike link:/tmp/dshws-s02-spike/pkg`；profile package.json `dependencies` + `dsh.profile.bundles` 自动追加 `["…dsh-base","…dsh-web-app","dsh-websearch-spike"]`（`dsh.bundle.patch` manifest 键生效）；boot 日志 `[dshws-spike] node half applied (base greeting: spike-hello)` 零 load 错误。tarball 腿：`pnpm pack`（6,690B）→ 同命令安装 → 依赖 spec 翻转 `file:/tmp/dshws-s02-spike/pkg/dsh-websearch-spike-0.1.0.tgz` → 重启后加载成功。附发现：非模板 profile 名无 webserver（base-only）——scratch 隔离必须 `web` 模板 + `DSH_HOME` 重定向（审核轮 1 F-001 预判与实测一致）

### H3 installSection describe/mutate 通路 —— **成立（热改 + 持久化）**

- **假设**：外置插件 node half installSection 注册的 namespace 经 remote describe 可见，mutate 后 onChange 热生效
- **验收标准**：describe 返回原文 + mutate 后 onChange 生效证据
- **结论与证据**：成立。describe：`{"ns":"dshws-spike","schema":{…},"value":{"greeting":"spike-hello"},"base":{…},"applies":"live","revision":0}`（浏览器探针日志原文）。mutate：`settings.mutate → ok (revision {…"value":{"greeting":"mutated-1788319702959"},"user":{…},"revision":1})`；服务端 node half 钩子同步输出 `[dshws-spike] settings onChange: {"greeting":"mutated-1788319702959"}`（web-instance2.log）；落盘 `settings.yaml: dshws-spike: greeting: mutated-…` 且跨重启存活（tarball 腿重启后 onChange 直接读出 persisted 值）。实现注记：经 provider 方法 `installSection` 调用（npm alpha.3/.4 无独立 `installSettingsSection` 导出，见 ADR-0007 依赖钉版策略）

### H4 client 经 remote 的 credentials 写通路 —— **成立（set/describe/事件/unset 全链）**

- **假设**：client half 经 `ctx.remote.credentials.set(ref, 伪值)` 后 describe 可见、`credentials/reference-updated` 事件到达 client、unset 回落
- **验收标准**：浏览器实测 set→describe→事件→unset→describe 回落；落盘仅伪值
- **结论与证据**：成立。探针日志原文（新在上）：`credentials.set(DSHWS_SPIKE_FAKE_KEY) → ok` → `event credentials/reference-updated: DSHWS_SPIKE_FAKE_KEY`（事件到达外置 client）→ `credentials.describe → {"configured":true,"source":"file","writable":true}` → `credentials.unset(DSHWS_SPIKE_FAKE_KEY) → ok` → 事件再次到达 → `credentials.describe → {"configured":false,"writable":true}`（回落）。磁盘核查：scratch `.credentials.yaml` refs 在 unset 后为空 `{}`；全程仅伪值 `sk-spike-fake-12345`，真实 `~/.dsh` 零接触

### H5 包名/版本起点/交付形态定谳 —— **定谳（ADR-0007）**

- **假设**：可定谳且有实测依据
- **验收标准**：ADR-0007 记录决策 + H2 对比证据 + npm 名称可用性实测
- **结论**：包名 `dsh-websearch`（npm E404 未占用实测，2026-09-02）；版本独立 `0.1.0` 起；交付路径/tarball 双形态、npm publish 延后 M6 后；依赖钉版策略吸收「npm 发布面滞后 dev 树」实测（`installSettingsSection` 不在 npm alpha.3/.4）。正本 = `docs/decisions/adr-0007-package-name-version-delivery.md`

## 踩坑 / 经验

- **坑（沉淀为 dont-do 第 2 条）**：npm `latest` dist-tag 失真——`npm view <pkg> version` 对 dsh 系包返回旧线（`@deepseek-ai/dsh-settings` latest 指向 0.0.1-rc.1，实际发布线 0.1.2-alpha.2..4）；钉版本必须看 `npm view <pkg> versions` 全列表。与 dont-do 第 1 条（版本域双实锚）同族，单独成条
- **坑**：macOS BSD grep 的 `--include` 会过滤显式文件参数（GNU grep 只作用于递归遍历）——口径敏感的验收 grep 优先 `--exclude-dir` + 逐行枚举，不裸引计数
- **经验**：cordis 运行时的细粒度 inject 强制（`remote.settings` 等）在开发期即 fail-loud，报错信息直接指明缺失项——外置 client half 的 inject 面照抄 `ui-settings-plugins` 范本即可一次到位
- **经验**：npm 发布面滞后 dev 树（alpha.3/.4 均缺 `installSettingsSection`）——外置插件应钉 npm 已有的稳定核心面（provider 方法），这同时天然兼容宿主 dev 树与发布线
- **经验**：`dsh plugin add` 的 reconcile 机制 + `dsh.bundle.patch` manifest 键 = 外置 bundle 自动接线的全部要件；spike 一次验证，S05b 端到端安装可直接复用
