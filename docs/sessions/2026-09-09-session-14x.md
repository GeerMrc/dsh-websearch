## 踩坑 / 经验

- **坑（locales 成对改写的原子性）**：批量 python 改 locales 时在 zh 某句断言失败中
  断，其后 zh 子命令全部静默未执行——en 侧四句改写完成而 zh 漏两句，撒谎文案逃逸到
  独立复审才被抓（i18n 门禁只查键 parity 不查内容真伪）。对策：locales.spec 增 zh/en
  双侧关键词防逃逸断言；改写类批量必须 en/zh 成对原子提交。
- **坑（探针变体盲区）**：④号自排除钉子只堵了「彻底不过滤」变体，「数 enabled 成员」
  变体 0 红（复审探针发现）——钉子测试要枚举实现回归的**变体空间**，不止一种写法。
- **经验（计划驳回的正确打开方式）**：两轮驳回（技术执行视角→产品对照书；补充规则）
  各自推动了实质改进——第一轮迫使交付形态从「技术任务清单」变成「用户可验收的对照
  表」；用户「不要把我定义为编程人员」的定位声明是重要的协作契约。
- **经验（三轮计划审核的复利）**：轮 1 抓迁移矛盾、轮 2 抓双字段缝、轮 3 抓自数自杀
  洞——每轮都在前轮定稿基础上向深一层；「审核不过就修计划」比「带着缝执行」便宜一个
  数量级。
