## 踩坑 / 经验

- **坑（本棒核心发现，潜伏三棒）**：`dsh.bundle.patch` 在 package.json 中必须写成**嵌套形态** `{"dsh":{"bundle":{"patch":…}}}`——S03 把文档里的「键名」转写成平铺顶层键，宿主读取语法（`manifest.dsh?.bundle?.patch`）从不触碰它，安装时以 `declares no dsh.bundle` 警告降级为普通依赖。教训：**「文档里的键名」≠「manifest 的 JSON 路径」**；凡声明宿主读取的 manifest 键，先 grep 宿主读取代码核对路径层级。缺陷能潜伏三棒，恰因安装端到端被排到 S05b——验证面缺位 = 缺陷温床
- **坑（流程，家族第 4 实例）**：T0 清偿 Y-1 时插入新里程碑行而旧行未删——「替换」操作在 Edit 工具语义下旧串不匹配即整段跳过，产物 = 双行并存。dont-do 第三条已增补「替换而非追加」；Edit 类替换后必须回读目标区域
- **经验**：`--dump-config` 是安装链路的理想观测面——与 boot 共用同一组合函数、无实例/无 LLM/无 key 即可读出最终选择标量；三态对照（基线/接线/复原）+ diff 零输出 = 机制级复原证据
- **经验**：`remove` 的 bundles reconcile（splice）行为可先从宿主源码预注册（S-5），实测对峙偏离即异常——「实测优先」与「源码预期」不矛盾，前者是事实源，后者是判别器
- **经验**：--allow-empty 证据 commit 用于实测棒（产物在 /tmp、证据在 message）——独立审核逐条核对 commit message 与 /tmp 文件双源互证，链条完整
