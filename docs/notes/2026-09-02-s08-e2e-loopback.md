## loopback helper 契约（tests/e2e/helpers/loopback-server.ts）

- `startLoopback(behavior)`：listen(0) 瞬时端口（零固定端口）；行为表
  `success/status/hang/destroy` 四形态——**destroy = 连接即断**（socket destroy →
  `TypeError: fetch failed`，与 ECONNREFUSED 在 fetch 面 observable 等价）；真连接拒绝只由
  `closedPort()`（起服→取端口→即关）承担；跨端点到达序日志 = 时序断言正本；
  close = `closeAllConnections()` + `close()`（hang handler 强制收口）。
- **每场景一服务器**：行为表不可变 + 端口每场景换——keep-alive 池无跨场景 bleed 路径。

## 场景-语义映射与断言面（M1 修正的落地）

- 失败痕迹的可观察面 = **logger 降级行**（`member <id> failed (<reason>); degrading…`）——
  reason 是成员 message 而非 code（core.ts:173-177），断言写 `<Label> search request
  failed` 前缀 / `HTTP 429` / `DSHWS_MEMBER_TIMEOUT`，不写成员码字面。
- **code 级断言只在异常对象在手处**：全败（EXHAUSTED + 逐成员行 + cause.code）与
  钉死直调（成员码原样）。
- 429 场景钉 tavily + body `{}`：unfoldHttpErrorDetail 对 exa/perplexity 是**替换**
  message（会丢 `HTTP 429` 字样）、对 tavily 是追加——线材与断言必须同钉。
- exa 线材坑：mapExaResult 丢弃无 snippet 条目——item 必须带 `highlights`，否则链
  成功返回空 sources（首轮 3 场景全红的根因，测试线材问题非产品码）。
- skip 成员不计序：`enabled: false` 走选择门跳过——不产生到达记录（选择跳过 ≠ 时序条目）。

## 牙齿证明（变异探针惯例）
