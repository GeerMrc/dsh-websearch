## 排序写通路（T2）

- `moveSearchChainEntry(id, delta)` 复刻 `setEnabled` 的通路形态：`settings.update(ns,
  patch, expectedRevision)` 全量数组 patch → 响应 `value`/`revision` 回填 → `#recompute`。
  链 getter 按调用时读值（`src/settings.ts` 模块注释），下次搜索即新序（S05a 已验锚点）。
- **物化语义**：在默认序上移动 = 把生效序物化为显式数组写入 settings——这是徽章翻
  pinned 的机制本身。移回默认序后 settings 仍显式（仍显示已钉死）：诚实口径，不做
  「值相等回落默认」的猜测（D1）。
- 边界与未知 id 在 controller 层 fail-fast（不触 remote）；冲突 not-ok 保持描述态。

## 钉死覆盖标记语义（D1 定谳）

- 标记 = settings 层：section 值显式在场（describe 只带 user-set 字段）= 已钉死，
  缺席 = 内置默认序。`deriveSnapshot` 两个布尔派生字段，零新增 remote 面。
- **组合标量层（`searchProvider`）不可达**：client half 观测面 = settings + credentials
  （inject 五面），组合标量属 cordis 组合层——显示它需新宿主面，违零内核侵入（ADR-0001）。
  GUI 上若用户 patch 钉死单成员直连，链不在调用路径（拓扑保证），本插件 v1 不显示该状态。

## i18n 门禁脚本（T4，零依赖 .mjs）

- `check-locales.mjs`：文本级解析 locales.ts 三锚点（union/en/zh），集合相等断言；
  与编译期 `Record` parity（cast 可逃逸）和运行时 spec 三层互补，门禁里跑的是它。
- `check-cjk.mjs`：`src/**/*.{ts,tsx}`（locales.ts 除外）状态机剥注释后扫 CJK 码位
  （含 CJK 标点/全形域）；字符串内容全保留。**block 注释剥离时保留换行**——否则命中
  行号漂移（首版实测 10 vs 实物 24，自证拒绝路径时抓获）。已知限制：`${}` 插值内
  注释不剥（本仓无此形态）。
- 拒绝路径是门禁验收的一部分：zh 独有键与 CJK 字面量注入各证 exit 1，临时态不入库。

## 测试坑

- **screen 全文档查询撞多实例**：同测试内二次 `render` 不卸载第一实例，
  `screen.queryByTestId` 会命中第一实例残留节点——断言「新实例无 X」必须容器内查询。
- section.spec 既有「双链只读」断言（`li.textContent` 等值）随排序按钮入列失效——
  id 包进 `<span>` 后断言 `li > span` 文本序，测试随行为同棒更新（非豁免）。
