## 需求正本

用户场景 (b)：三家及以上搜索成员都配好多 key 启用后，把内置兜底（deepseek/fetch）置换
成链内用户自选成员作兜底工具，其余成员遵循现行链规则。

## 现行约束（为何今天做不到——三层钉死）

1. **决策层**：ADR-0004 D3 + ADR-0013 D6（S14c 注记）「五家排序域 + DeepSeek 固定链尾
   兜底」——链尾二元地板是被 ADR 显式裁决的产品约束，非实现偶然。
2. **代码层**：`config.ts:38`（`FallbackProvider = 'deepseek' | 'fetch' | 'auto'`）、
   `config.ts:60-63`（withFallbackTail 剥双兜底 id 后只回填 deepseek/fetch）、
   `index.ts:165-175`（order getter 每请求强制替换链尾元素）。
3. **GUI 层**：`section.tsx:546-597` 兜底行只有两按钮；`controller.ts:160-162` 快照投影
   二元化（GUI 从不写 auto）。

## 三条待定义规则（设计决策，开工时定谳并写 ADR）

1. **重复入链去重**：被点名为尾的成员若也在用户排序域中，先试后尾 = 同成员两次入场
   ——需定义（排序域剥离〔与 deepseek 同构，推荐〕还是尾位跳过已试成员）。
2. **点名尾失效语义**：尾成员 key 未配/未就绪时——fail-loud（诚实不可用，与显式付费
   兜底无 key 同构）还是回落内置地板（保可用性但静默换行为）。治理倾向 fail-loud。
3. **耗尽摘要/降级语义**：成员尾自身 3 draw 语义照抄即可（S14u 定稿），但「成员尾后无
   更低地板」时的终态文案需定义（链尽 = 用户自选的最后一道网已破）。
